# বদলের দিন (cutover) — Vercel থেকে নিজের সার্ভারে (VPS)

এখন যা চলছে:

| কী | কোথায় | কে ব্যবহার করে |
|---|---|---|
| পুরোনো সার্ভার (Node) + ওয়েব (React) + অ্যাডমিন | Vercel — `https://blood-server-ashy.vercel.app`, তথ্য Firestore-এ | প্রকাশিত ফোনের অ্যাপ, সবাই |
| নতুন সার্ভার (Spring) + তথ্য PostgreSQL-এ | VPS `169.58.58.176` — `https://api.lifolo.com` | এখনো কেউ না (শুধু পরীক্ষা আর ডেমো) |
| নতুন ওয়েব (Vue) + নতুন অ্যাডমিন | VPS — `https://lifolo.com` (`www` → `lifolo.com`) | এখনো কেউ না |

Firebase (লগইন আর পুশ) দুই সার্ভারেরই এক — তাই একই অ্যাকাউন্টে দুই জায়গাতেই লগইন হয়।
ডেমোর অ্যাকাউন্টগুলোও এক: VPS-এ `DEMO_KEEP_FIREBASE_USERS=true`, তাই নতুন সার্ভারে "ডেমো মুছুন" চাপলেও Firebase-এর
ডেমো অ্যাকাউন্ট থেকে যায় (Vercel-এর ডেমো ভাঙে না)।

VPS-এ নতুন কোড বসানো সবসময় একভাবেই: **Actions → Deploy backend → Run workflow → branch `spring`**
(ডেমো `keep`, ওয়েবসাইট `lifolo.com`, আলাদা নাম `api.lifolo.com`)। ৫–১০ মিনিট পর Summary-তে সব ✅।

## আগে থেকে (বদলের দিনের আগেই শেষ থাকবে)

1. **তথ্য সরানো (Firestore → PostgreSQL) — এখনো বানানো হয়নি, এটাই সবচেয়ে বড় কাজ।**
   নতুন সার্ভারের ডাটাবেস এখন খালি (শুধু ডেমো)। আসল ব্যবহারকারীদের রক্তের রিকোয়েস্ট, ফার্মেসি, ডাক্তার, প্রেসক্রিপশন,
   হিসাব-খাতা ইত্যাদি Firestore থেকে PostgreSQL-এ আনার একটা একবারের টুল লাগবে (`backend/docs/SCHEMA.md`-এ কোন
   collection কোন টেবিলে যায় লেখা আছে)। টুলটা আগে কয়েকবার পরীক্ষা করে চালাতে হবে (VPS-এর ডাটাবেসে, Vercel চালু রেখেই)।
   এটা না হওয়া পর্যন্ত বদল করা যাবে না।
2. **Amazon SES production access** অনুমোদিত (না হলে লগইন-কোডের ইমেইল শুধু যাচাই করা ঠিকানায় যায়)।
   অনুমোদনের পর অচেনা একটা ঠিকানা দিয়ে `https://lifolo.com/admin/`-এ একবার লগইন করে দেখুন।
3. **নতুন অ্যাপ পরীক্ষা:** নিচের "Android" অংশের `next` APK ফোনে বসিয়ে মূল কাজগুলো (লগইন, রক্তের রিকোয়েস্ট,
   ফার্মেসিতে প্রেসক্রিপশন, অ্যাম্বুলেন্স ডাকা, ডাক্তারের সিরিয়াল) চালিয়ে দেখা।
4. Deploy backend সর্বশেষ `spring` থেকে সফল (Summary-তে সব ✅), আর
   `https://lifolo.com`, `https://lifolo.com/admin/`, `https://api.lifolo.com/api/health` খোলে।
5. VPS-এর ব্যাকআপ চালু (Setup VPS (base) এটা বসায়) — বদলের আগের দিন একটা ব্যাকআপ হয়েছে কি না দেখে নিন।

## বদলের দিন — ধাপে ধাপে

সময় বাছুন যখন ব্যবহার সবচেয়ে কম (যেমন রাত ২টা)। মোট ১–২ ঘণ্টা।

1. **ঘোষণা:** অ্যাপে/ফেসবুকে "আজ রাত ২টা থেকে ৩০ মিনিট নতুন কিছু লেখা যাবে না" (ঐচ্ছিক, কিন্তু ভালো)।
2. **পুরোনো সার্ভারে লেখা বন্ধ (ঐচ্ছিক কিন্তু নিরাপদ):** তথ্য সরানোর সময় কেউ নতুন রিকোয়েস্ট দিলে সেটা হারাবে।
   সবচেয়ে সহজ: তথ্য সরানোর টুলটা দুবার চালানো (প্রথমবার পুরোটা, দ্বিতীয়বার শেষ কয়েক ঘণ্টার বদল) — টুলটা সেভাবেই বানাতে হবে।
3. **তথ্য সরানো:** টুল চালিয়ে PostgreSQL-এ সব আনা; সংখ্যা মিলিয়ে দেখা (ব্যবহারকারী, রিকোয়েস্ট, ফার্মেসি …)।
   VPS-এর ডেমো থাকতে পারে — ডেমো আর আসল তথ্য আলাদা থাকে (`demo-` দিয়ে শুরু uid)।
4. **নতুন সার্ভার শেষবার বসানো:** Actions → Deploy backend → `spring`। Summary-তে সব ✅।
5. **শেয়ার লিংক:** Summary-র নিচে "শেয়ার লিংক/QR-এর ঠিকানা" = `https://lifolo.com` কি না দেখুন (DNS ঠিক থাকলে নিজে থেকেই)।
6. **ফোনের অ্যাপ নতুন সার্ভারে:** স্বাভাবিক নতুন সংস্করণ (version বাড়িয়ে) — বিস্তারিত নিচে "Android" অংশে।
   নতুন APK `latest` রিলিজে গেলে পুরোনো অ্যাপ "নতুন সংস্করণ আছে" দেখায়; যারা আপডেট করে তারা নতুন সার্ভারে যায়।
   যারা করেনি তারা কিছুদিন Vercel-এ থাকে — তাই Vercel **এখনই বন্ধ নয়** (নিচে "পরে")।
7. **Cloudflare proxy চালু (কমলা মেঘ):**
   1. Cloudflare → SSL/TLS → **Full (strict)** (VPS-এ Let's Encrypt সার্টিফিকেট আছে)।
   2. DNS → `@` (lifolo.com), `www` আর `api` রেকর্ডে মেঘে চাপ দিয়ে কমলা (Proxied)।
   3. VPS আসল দর্শকের IP Cloudflare-এর `CF-Connecting-IP` থেকে নেয় (শুধু Cloudflare-এর ঠিকানা থেকে এলে) — অতিথির সীমা আর
      লগইন-কোডের সীমা ঠিক থাকে। এটা আগে থেকেই বসানো, কিছু করতে হবে না।
   4. `/w/assets/` আর `/admin/assets/`-এর ফাইলে এক বছরের cache — Cloudflare নিজে থেকেই জমা রাখে; পাতা (`/`, `/admin/`) আর
      `/api` কখনো জমা হয় না (no-cache / অ্যাপের নিজের হেডার)। "Cache Everything" নিয়ম দেবেন **না**।
   5. Let's Encrypt-এর নবায়ন proxy চালু থাকলেও চলে (`/.well-known/acme-challenge/` http আর https দুটোতেই খোলা)।
   6. চালুর পর: `https://lifolo.com`, `https://lifolo.com/admin/`, `https://api.lifolo.com/api/health` আবার খুলে দেখুন।
      ⚠️ `/api/events` (সরাসরি ধারা, SSE): ১০০ সেকেন্ড কিছু না এলে Cloudflare সংযোগ কেটে দেয়; Spring এখন কোনো "ping"
      পাঠায় না। proxy চালুর আগে দেখে নিন যারা এটা ব্যবহার করে (যেমন ডাক্তারের সিরিয়ালের সরাসরি তালিকা) কাটার পর আবার জোড়ে কি না;
      না জুড়লে Spring-এ প্রতি ৩০ সেকেন্ডে একটা খালি মন্তব্য পাঠানো যোগ করতে হবে।
8. **নজর রাখা (প্রথম ২৪ ঘণ্টা):** Uptime check-এর ইমেইল, Sentry (চালু থাকলে), অ্যাডমিন প্যানেলের রিপোর্ট আর টিকিট।

## পরে (১–৪ সপ্তাহ, বেশিরভাগ ব্যবহারকারী নতুন সংস্করণে যাওয়ার পর)

1. **Vercel-এর deploy hook বন্ধ:** `server/vercel.json`-এ আগে থেকেই `git.deploymentEnabled: false`; Vercel-এর
   ড্যাশবোর্ডে Deploy Hook থাকলে মুছে দিন (যাতে ভুলে কেউ পুরোনো কোড না বসায়)। প্রকল্প **মুছবেন না** — ফেরার রাস্তা।
2. **পুরোনো অ্যাপের জন্য:** Vercel-এ শুধু একটা পাতা রাখা যায় "নতুন সংস্করণ নামান" — তখনই, যখন প্রায় সবাই আপডেট করেছে।
3. **Firestore:** প্রথমে শুধু-পড়া (Firestore rules-এ লেখা বন্ধ), এক মাস পর একটা পুরো export (Google Cloud → Firestore →
   Import/Export → Cloud Storage), তারপর ইচ্ছে হলে মোছা। **export ছাড়া কখনো মুছবেন না।**
4. **`DEMO_KEEP_FIREBASE_USERS`:** Vercel-এর ডেমো আর না থাকলে GitHub secret `DEMO_KEEP_FIREBASE_USERS` = `false` দিয়ে
   Deploy backend আবার চালান — তখন "ডেমো মুছুন" Firebase-এর ডেমো অ্যাকাউন্টও মোছে।
5. `vercel.json`-এর cron (`/api/cron/daily`) — নতুন সার্ভারে নিজের ভেতরের কাজ (JobRunr) এটা করে; Vercel বন্ধ হলে কিছু লাগবে না।

## ফেরা (rollback)

যেকোনো ধাপে কিছু ভুল হলে — **Vercel পুরোটা আগের মতোই চালু আছে**, তাই ফেরা সহজ:

| কী ভেঙেছে | কী করবেন |
|---|---|
| নতুন ফোনের অ্যাপ (নতুন সার্ভারে) কাজ করছে না | আগের সংস্করণের কোড থেকে আরেকটা নতুন সংস্করণ (version আরও বাড়িয়ে, ঠিকানা Vercel) — `latest`-এ গেলে সবাই আবার Vercel-এ। নিচে "Android" দেখুন। |
| lifolo.com-এর ওয়েব ভুল দেখাচ্ছে | VPS-এ আগের ওয়েব: `ln -sfn /var/www/lifolo-site/releases/<আগেরটা> /var/www/lifolo-site/current` (Summary-তে "আগেরটা"-র নাম আছে; reload লাগে না)। অথবা আগের commit থেকে Deploy backend আবার। |
| নতুন সার্ভার (Spring) চালু হচ্ছে না | Deploy backend নিজেই আগের jar-এ ফেরে ("আগের jar-এ ফেরা")। হাতে: `/opt/lifolo/api/app.jar.prev` → `app.jar`, `systemctl restart lifolo-api`। |
| Cloudflare proxy চালুর পর সমস্যা | Cloudflare-এ মেঘ আবার ধূসর (DNS only) — কয়েক মিনিটে সরাসরি VPS। |
| পুরো VPS-ই সমস্যায় | Cloudflare-এ `lifolo.com` আর `www`-এর রেকর্ড Vercel-এর দিকে (Vercel-এ ডোমেইন যোগ করে) বা সরিয়ে দিন; অ্যাপের পুরোনো সংস্করণ Vercel-এই যায়। |
| বদলের পরে লেখা নতুন তথ্য | নতুন সার্ভারে লেখা তথ্য Firestore-এ ফেরে না। তাই বদলের প্রথম কয়েক দিনেই ফেরার সিদ্ধান্ত নিন; দেরিতে ফিরলে উল্টো দিকে তথ্য আনার টুল লাগবে। |

## Android

> এই অংশ Android-এর কাজ (আলাদা branch `cutover-android`) শেষ হলে লেখা হবে: অ্যাপের সার্ভারের ঠিকানা কোথায় বদলায়,
> `next` APK (`lifolo-next.apk`, রিলিজ `next`) কীভাবে বানায় আর বসায়, `latest`-এ ফেরা, আর বদলের দিনের
> সংস্করণ বাড়ানো (version bump)।
