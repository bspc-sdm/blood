# নতুন VPS-এর ভিত্তি তৈরি — এক বোতামে

এই কাজটা নতুন Contabo VPS-কে (IP `169.58.58.176`) প্রস্তুত করে: নিরাপত্তা (ফায়ারওয়াল, আপডেট), ডাটাবেস (PostgreSQL),
Redis, Java 21, ওয়েব সার্ভার (nginx) আর HTTPS সার্টিফিকেট, আর প্রতিদিনের ব্যাকআপ। এখনকার অ্যাপ (Vercel) যেমন চলছে তেমনই

# নতুন ব্যাকএন্ড (Spring) VPS-এ চালু করা — "Deploy backend"

ভিত্তি তৈরির (ওপরের "Setup VPS (base)") পরে এই কাজটা নতুন সার্ভারের কোড (Kotlin/Spring, `spring` branch) VPS-এ বসায়,
ডাটাবেসের টেবিল বানায়, চালু করে, আর নিজে নিজে পরীক্ষা করে। এখনকার অ্যাপ (Vercel) তবুও আগের মতোই চলবে —
ফোনের অ্যাপ বা ওয়েব এখনো নতুন সার্ভারে যায় না।

মোট সময়: ২ মিনিট আপনার, ৫–১০ মিনিট GitHub-এর।

## ধাপ ১ — সিক্রেট (একবারই)

**Settings → Secrets and variables → Actions → New repository secret** (ওপরের ধাপ ১-এর মতোই):

| নাম | কী দেবেন | না দিলে |
|---|---|---|
| `VPS_HOST`, `VPS_ROOT_PASSWORD` | আগেরগুলোই (বদলাবেন না) | কাজ চলবেই না |
| `FIREBASE_SERVICE_ACCOUNT` | Firebase console → Project settings → Service accounts → **Generate new private key** — নামানো JSON ফাইলটা খুলে পুরো লেখা | অ্যাপ চলবে, কিন্তু **কেউ লগইন করতে পারবে না, পুশ বন্ধ** — সারাংশে লেখা থাকবে |
| `ADMIN_EMAILS` | ঐচ্ছিক — মালিকদের ইমেইল, কমা দিয়ে | `ekapkbd@gmail.com` |
| `SES_REGION`, `SES_ACCESS_KEY_ID`, `SES_SECRET_ACCESS_KEY`, `SES_FROM` | ঐচ্ছিক — Amazon SES (লগইন-কোডের ইমেইল) | ইমেইল যায় না (কোড শুধু VPS-এর লগে) |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` | ঐচ্ছিক — Cloudflare R2 (ছবি) | বন্ধ |
| `SENTRY_DSN` | ঐচ্ছিক — ত্রুটির খবর | বন্ধ |

> ⚠️ service account-এর JSON ফাইল বা কোনো চাবি চ্যাটে (Claude, WhatsApp, ইমেইল) পেস্ট করবেন না — শুধু GitHub-এর সিক্রেটের ঘরে।

## ধাপ ২ — চালান

1. রিপোর **Actions** ট্যাব → বাঁ দিকে **Deploy backend**।
2. ডান দিকে **Run workflow** → **Use workflow from**-এ **`spring`** বেছে নিন (main নয়)।
3. "ডেমো বানিয়ে আবার মুছে পরীক্ষা" টিক দেওয়া থাকুক → সবুজ **Run workflow**।
4. ৫–১০ মিনিট পর লাইনের পাশে সবুজ ✓ আর নিচে **Summary**।

## সফল হলে কেমন দেখায়

- Summary-তে **✅ ব্যাকএন্ড চালু হয়েছে**, আর একটা টেবিলে প্রতিটা পরীক্ষার পাশে ✅ / ❌ / ⏭️ (বাদ):
  অ্যাপ চালু, ডাটাবেস migration, nginx-এর পথ, ভেতর আর বাইরে থেকে `/api/health`, `/healthz`, শেয়ার পাতা,
  JobRunr dashboard আর `/actuator` বাইরে বন্ধ, ডেমো বানানো আর মোছা।
- এই ঠিকানা খুললে `{"ok":true,...}`: **https://169-58-58-176.sslip.io/api/health**
- `https://169-58-58-176.sslip.io/healthz` আগের মতোই কাজ করে।
- **api.lifolo.com:** Run workflow-এর "আলাদা নাম" ঘরে আগে থেকেই `api.lifolo.com` লেখা থাকে। Cloudflare-এ A রেকর্ড
  `api` → `169.58.58.176` (**DNS only**, ধূসর মেঘ) থাকলে নিজে থেকেই সার্টিফিকেট নেয় আর **https://api.lifolo.com/api/health**
  চালু করে; DNS এখনো না পৌঁছালে সারাংশে ⏭️ — কিছু ভাঙে না, কয়েক মিনিট পর আবার চালালেই হবে। sslip.io-র ঠিকানাও চলতে থাকে।

**ডেমো (গাজীপুর):** "ডেমো" ঘরে `keep` (ডিফল্ট) — ডেমো না থাকলে বানায় আর রেখে দেয়, তারপর ইন্টারনেট থেকে
`https://api.lifolo.com` দিয়ে ডেমো লগইন আর কয়েকটা পড়া পরীক্ষা করে। `smoke` = বানিয়ে আবার মোছা, `off` = হাত নয়।
Firebase-এর ডেমো অ্যাকাউন্ট Vercel-এর ডেমোরও — তাই এই সার্ভারে `DEMO_KEEP_FIREBASE_USERS=true`: অ্যাডমিন প্যানেলের
"ডেমো মুছুন" শুধু এখানকার ডাটাবেস মোছে, Firebase-এর অ্যাকাউন্ট নয়; "ডেমো বানান" থাকা অ্যাকাউন্টগুলোই নেয়।

**ওয়েবসাইট (lifolo.com):** "ওয়েবসাইটের নাম" ঘরে `lifolo.com` (ডিফল্ট) — Vue ওয়েব (`/w/`), Vue অ্যাডমিন (`/admin/`),
Vercel-এর বাকি পথ আর হেডার হুবহু, `/api` এই সার্ভারে; `www.lifolo.com` → `lifolo.com`। Cloudflare-এ `@` (A) আর `www`
(CNAME) DNS only থাকলে নিজে থেকেই সার্টিফিকেট নেয়; না থাকলে সারাংশে ⏭️ আর বাংলায় কী করতে হবে। বদলের দিনের ধাপ:
[CUTOVER.md](CUTOVER.md)।

## জেনে রাখুন

- অ্যাপের সেটিং VPS-এর `/etc/lifolo/app.env`-এ (শুধু root পড়তে পারে); ডাটাবেস/Redis-এর পাসওয়ার্ড `/etc/lifolo/env`-এ।
